# LifeTrace Assets UI Design V1

## 1. 产品目标

LifeTrace Assets 是独立的个人资产记录 App，核心问题不是“花了多少钱”，而是：

- 我现在拥有什么？
- 它们目前值多少钱？
- 一件东西每天真实成本是多少？
- 哪些东西在高频使用，哪些已经闲置？
- 一件资产经历过哪些购买、维护、维修、借出、出售和退役事件？

产品参考个人资产全生命周期管理类应用的思路，但界面与交互采用 LifeTrace 自己的设计体系。

## 2. 一级导航

固定 5 个一级入口：

1. **首页**：资产总览、常用设备、提醒。
2. **资产**：完整资产库、搜索、状态筛选。
3. **记录**：跨资产生命周期时间线。
4. **分析**：价值、分类、保值率、日均成本和状态分析。
5. **我的**：LifeTrace Cloud、跨应用关联、隐私、备份、外观。

## 3. 首页

信息顺序：

```text
LifeTrace 品牌头
  ↓
我的资产 / 产品解释
  ↓
资产总览黄色主卡
  ↓
分类快速筛选
  ↓
常用设备
  ↓
资产提醒
```

主卡展示：资产数量、累计购入、当前估值、即将过保数量。

资产行必须同时让用户看到：

- 资产名称
- 分类与品牌
- 当前状态
- 购买价格
- 当前估值
- 日均成本
- 使用时间/服务进度
- 保值率

首页强调“我拥有的东西正在怎样为我服务”，避免做成财务记账首页。

## 4. 资产列表

顶部提供搜索和状态筛选：全部 / 使用中 / 闲置 / 借出 / 维修中 / 已出售 / 已退役。

列表默认按购买时间排序，并支持：当前估值、日均成本、保值率、更新时间。

点击资产整行进入详情；状态标签只展示，不承担点击行为。

## 5. 资产详情

页面结构：

```text
设备主信息
  ↓
购买价 / 当前估值 / 日均成本
  ↓
持有时间 / 保值率
  ↓
设备信息
  ↓
使用与保修
  ↓
关联内容
  ↓
生命周期时间线
  ↓
添加记录
```

序列号、IMEI、订单号等敏感字段默认遮罩。

关联内容已由独立 EntityLink OpenSpec change 接入真实数据：展示持久化目标类型、稳定实体 ID、关系类型和可选显示名，并支持添加/删除。Assets 不为展示关系而读取或伪造 Finance / Execute / Notes 等目标实体正文。

## 6. 新增 / 编辑资产

表单分组：

### 基础信息

名称、分类、品牌、型号、规格、所在位置。

### 购买与价值

购买日期、购买价格、购买渠道、当前估值。

### 设备与保修

序列号/SN、保修截止。序列号在详情页默认遮罩，可显式复制原值。

### 当前状态

使用中、闲置、借出、维修中、已出售、已退役。

V1 不保存二进制图片或附件；图片、发票、说明书和 AI 抠图由后续文件能力 change 接入。

## 7. 生命周期记录

事件类型包括：

- 购入
- 开始使用/设为主力
- 维修
- 保养
- 更换配件
- 借出/归还
- 闲置
- 估值变化
- 出售
- 退役/报废

每个事件至少保存：资产 ID、时间、事件类型、标题、说明、费用/回收金额（适用时）。V1 不包含附件引用。

## 8. 成本口径

基础日均成本：

```text
日均成本 = (买入价 + 累计维护支出 - 已回收金额) / 有效持有天数
```

当前实现已按该完整公式计算：维修、保养、更换配件计入维护支出，出售事件计入已回收金额，并对负成本和零购入价做保护。

## 9. 视觉规范

- Primary：#F5C400
- Background：#F8F8F4
- Ink：#111111
- Surface：#FFFFFF
- Border：#E6E6DE
- Primary Container：#FFF0A3
- Warning / Tertiary：#B98500
- 卡片主要使用浅边框，不堆叠重阴影。
- 首页总览卡使用黄色渐变作为主要强调区域。
- 列表和详情尽量保持高信息密度，避免“每个字段一张卡”的 AI 卡片化布局。

## 10. 当前实现状态

基础 OpenSpec change `implement-assets-v1` 已归档。当前 `implement-asset-entity-links-v1` 在不扩大其他产品数据权限的前提下接入真实跨应用 EntityLink；二进制附件、可配置主题和后台系统通知仍需后续独立 OpenSpec change。
