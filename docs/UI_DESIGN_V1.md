# LifeTrace Assets UI Design V1

## 1. 产品目标

LifeTrace Assets 是独立的个人资产记录 App，核心问题不是“花了多少钱”，而是：

- 我现在拥有什么？
- 它们目前值多少钱？
- 一件东西每天真实成本是多少？
- 哪些东西在高频使用，哪些已经闲置？
- 一件资产经历过哪些购买、维护、维修、借出、出售和退役事件？

产品参考个人资产全生命周期管理类应用的思路，但界面与交互采用 LifeTrace 自己的设计体系。

## 2. 一级导航

固定 5 个一级入口：

1. **首页**：资产总览、常用设备、提醒。
2. **资产**：完整资产库、搜索、状态筛选。
3. **记录**：跨资产生命周期时间线。
4. **分析**：价值、分类、保值率、日均成本和状态分析。
5. **我的**：LifeTrace Cloud、跨应用关联、隐私、备份、外观。

## 3. 首页

信息顺序：

```text
LifeTrace 品牌头
  ↓
我的资产 / 产品解释
  ↓
资产总览蓝色主卡
  ↓
分类快速筛选
  ↓
常用设备
  ↓
资产提醒
```

主卡展示：资产数量、累计购入、当前估值、即将过保数量。

资产行必须同时让用户看到：

- 资产名称
- 分类与品牌
- 当前状态
- 购买价格
- 当前估值
- 日均成本
- 使用时间/服务进度
- 保值率

首页强调“我拥有的东西正在怎样为我服务”，避免做成财务记账首页。

## 4. 资产列表

顶部提供搜索和状态筛选：全部 / 使用中 / 闲置 / 借出 / 维修中 / 已出售 / 已退役。

列表默认按购买时间排序，后续支持：价值、日均成本、保值率、更新时间。

点击资产整行进入详情；状态标签只展示，不承担点击行为。

## 5. 资产详情

页面结构：

```text
设备主信息
  ↓
购买价 / 当前估值 / 日均成本
  ↓
持有时间 / 保值率
  ↓
设备信息
  ↓
使用与保修
  ↓
关联内容
  ↓
生命周期时间线
  ↓
添加记录
```

序列号、IMEI、订单号等敏感字段默认遮罩。

关联内容预留：

- Finance：购买账单、出售收入、维修支出
- Collection：发票、保修凭证、图片、说明书
- Calendar：保修和维护提醒
- Execute：维修、更换配件、出售等任务

## 6. 新增 / 编辑资产

表单分组：

### 基础信息

名称、分类、品牌、型号、规格、图片。

### 购买与价值

购买日期、购买价格、购买渠道、当前估值。

### 设备与保修

序列号/SN、IMEI（适用时）、保修截止、发票与凭证。

### 当前状态

使用中、闲置、借出、维修中、已出售、已退役。

图片区域后续允许接 AI 抠图，但 AI 不是录入资产的前置条件。

## 7. 生命周期记录

事件类型包括：

- 购入
- 开始使用/设为主力
- 维修
- 保养
- 更换配件
- 借出/归还
- 闲置
- 估值变化
- 出售
- 退役/报废

每个事件至少保存：资产 ID、时间、事件类型、说明、费用/回收金额（适用时）、附件引用。

## 8. 成本口径

基础日均成本：

```text
日均成本 = (买入价 + 累计维护支出 - 已回收金额) / 有效持有天数
```

当前 UI V1 在 Mock 阶段只用买入价 / 持有天数展示，正式业务实现时再接维护成本和出售回收金额。

## 9. 视觉规范

- Primary：#2563EB
- Background：#F7F9FC
- Ink：#18212F
- Muted：#7A8797
- Border：#E8ECF2
- Success：#159A66
- Warning：#D08A14
- 卡片主要使用浅边框，不堆叠重阴影。
- 首页总览卡允许使用蓝色渐变作为唯一强视觉区域。
- 列表和详情尽量保持高信息密度，避免“每个字段一张卡”的 AI 卡片化布局。

## 10. 当前原型说明

当前 `feature/flutter-ui-v1` 只用于 UI 与交互评审，使用 Mock 数据，不代表业务层已实现。设计确认后再拆 Domain / Repository / Local-first / LifeTrace Cloud Sync。
